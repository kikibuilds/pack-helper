这些 PDF 是自动截获或手动抓到的，还没确定属于哪个订单。选择订单后点「分配」。

订单

流程：①「一键拉取订单」把各平台待发货的订单和面单拉到这里 → ② 检查、修改（改过的内容重新拉取时会保留） → ③ 勾选要发的，点「打包下载」生成发货文件。
面单一栏：✓ 已对应 可以点「打开」查看；缺面单 会写原因，可以点「订单页」去平台下载，再「选择」或把 PDF 拖进这一格。

设置

发货文件保存位置

发货文件保存在：Chrome 的「下载内容」文件夹 / 发货 / 发货_日期时间 /
这里可以改子文件夹的名字（可以多层，例如 发货/2026）。要换整个根目录（比如换到另一个磁盘），请到 Chrome 的「设置 → 下载内容 → 位置」里改 —— Chrome 只允许扩展把文件存在下载文件夹里面。
改了子文件夹不影响发邮件。

子文件夹

待发货列表页地址

「一键拉取订单」会依次打开这些页面。第一格填列表页地址（留空表示跳过该平台）；第二格填打开后要先点的筛选按钮上的文字，例如 Depop 的「To ship」。

订单详情链接规则

一键拉取时用来识别订单详情链接的规则（正则）。平台改版后读不到时，在这里调整。

邮件

「✉ 打包并发邮件」打包后，会直接交给 Mac 上的邮件程序，用下面的发件邮箱发给选中的收件人，页面上会显示发送成功或失败；只点「打包下载」不会发邮件。
发件邮箱需要是 Gmail，并且在 Mac 上运行过一次这个版本的 mailer/install.sh，为这个邮箱保存应用专用密码（换发件邮箱后也要为新邮箱运行一次）。
